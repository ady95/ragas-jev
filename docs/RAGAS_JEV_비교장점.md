# RAGAS-JEV의 정량적 장점: 기존 RAGAS 대비

- 기준: 2026-09-24, JEV `jev-1.13.0`, 비교 대상 `ragas` 0.4.3. 두 시스템 모두 LLM 판정 모델은 `gpt-6-sol`이다
- 출처: [Phase 6 벤치마크 리포트](reports/phase6_benchmark.md). Phase 1~5 리포트([reports/](reports/))의 요청 단위 지연도 함께 썼다
- 관련 문서: [평가 항목 비교](ragas-jev_평가항목.md)

이 문서는 RAGAS-JEV가 RAGAS보다 나은 점 중 **숫자로 보일 수 있는 것**만 모았다. 처리 속도, 정확도, 재현성, 비용 순서로 정리했다. RAGAS가 앞서거나 비슷한 항목도 빼지 않고 7절에 적었다.

표기 규칙:

- "a / b"는 한국어 / 영어다.
- **RAGAS-JEV**는 권장 구성인 **Hybrid**를 가리킨다. Hybrid는 JEV 판정, 확률 보정, 일부 단위의 LLM 재판정으로 이루어진다.
- **JEV만**은 보정과 재판정 없이 JEV 판정만 쓴 결과다.

## 2. 처리 속도

### 2.1 측정 방식

| 시스템 | 측정 방식 |
|---|---|
| RAGAS | 벤치마크에서 샘플 단위로 직접 잰 p50 지연 |
| RAGAS-JEV | Phase 1~5에서 잰 요청 단위 p50을 더한 **추정치** |

RAGAS-JEV 추정에 쓴 값:

- JEV 요청 1회: 약 0.3초
- 분해용 LLM 호출 1회: 6.5~9.8초
- 재판정용 LLM 호출 1회: 약 5~8초

Hybrid 지연은 기댓값이다. "JEV 지연 + 재판정 확률 × LLM 1회 지연"으로 계산했다. 재판정하지 않는 샘플이 과반이라, Hybrid의 p50은 JEV만의 값과 같다.

### 2.2 판정 단계

평가 단위를 나누는 단계는 빼고, 판정에 걸리는 시간만 비교했다. Context Precision은 분해 단계가 없으므로 이 표의 값이 곧 전체 지연이다.

| metric | RAGAS | JEV만 | Hybrid (기댓값) | 속도 향상 (JEV만 / Hybrid) |
|---|---|---|---|---|
| Context Precision, 질문만 봄 (MIRACL) | 5.0초 (`ContextRelevance`, LLM 2회) | 0.3초 | 약 3.5초 (0.3 + 0.40 × 8) | **17배 / 1.4배** |
| Context Precision, reference 사용 | 21.2 / 19.0초 (LLM 5회) | 0.3초 | 약 2.5 / 3.7초 (0.3 + 0.28~0.42 × 8) | **63~71배 / 5~8배** |

RAGAS는 context마다 LLM을 한 번씩 부른다. 따라서 **검색 결과(top-k)가 많을수록 차이가 커진다.** RAGAS-JEV는 context가 몇 개든 JEV 요청 1회로 판정한다.

### 2.3 처음 평가할 때 (분해 포함)

| metric | RAGAS | JEV만 | Hybrid (기댓값) | 속도 향상 (JEV만 / Hybrid) |
|---|---|---|---|---|
| Faithfulness | 16.8초 | 약 10.1초 (분해 9.8 + JEV 0.3) | 약 11.8초 (+ 0.34 × 5) | **1.7배 / 1.4배** |
| Context Recall | 9.1초 | 약 9초 (분해 8~9 + JEV 0.3) | 약 9초 (재판정 없음) | 비슷함 |
| Answer Relevancy | 9.1초 | 약 7~8초 (분해 6.5~7.8 + JEV 0.3) | 약 7~8초 (재판정 없음) | **1.1~1.3배** |

처음 평가할 때는 LLM 분해가 시간의 대부분을 차지한다. 그래서 차이가 작다.

### 2.4 다시 평가할 때 (분해 결과 캐시 사용)

RAGAS-JEV는 분해 결과를 캐시한다. 같은 답변이나 reference를 다시 평가하면 분해를 건너뛰고 JEV만 호출한다. 이번 벤치마크의 RAGAS 설정(ragas 기본값)은 매번 처음부터 다시 분해했다.

| metric | RAGAS | JEV만 | Hybrid (기댓값) | 속도 향상 (JEV만 / Hybrid) |
|---|---|---|---|---|
| Faithfulness | 16.8초 | 0.3초 | 약 2.0초 | **56배 / 8배** |
| Context Recall | 9.1초 | 0.3초 | 0.3초 | **30배** |
| Answer Relevancy | 9.1초 | 0.3초 | 0.3초 | **30배** |

실제로 이런 재평가가 흔하다. 검색기만 바꿔 A/B 테스트하는 경우를 보자. Context Recall의 분해 결과는 질문과 reference에만 의존하고, context가 바뀌어도 그대로 쓸 수 있다. 그래서 JEV 판정만 다시 하면 된다.

### 2.5 처리량

- JEV 호출 한도는 1,200 RPM이고, 한 요청에 여러 문항을 담을 수 있다.
- 샘플 하나의 한 metric을 요청 1회로 판정하므로, 분당 약 1,200 샘플-metric을 판정할 수 있다. 긴 context를 나눠 판정하면 요청 수가 늘어난다.
- RAGAS는 판정할 때마다 LLM 호출이 1~5회 필요하다. 따라서 처리량은 LLM 쪽 호출 한도에 묶인다.

## 3. LLM 호출 수와 비용

| metric | RAGAS 판정용 LLM 호출/샘플 | RAGAS-JEV 판정용 LLM 호출/샘플 | 감소 | 분해용 LLM 호출/샘플 (RAGAS / RAGAS-JEV) |
|---|---|---|---|---|
| Context Precision (질문만 봄) | 2 | 0.40 | **80%** | 0 / 0 |
| Context Precision (reference 사용) | 5 | 0.28~0.42 | **92~94%** | 0 / 0 |
| Faithfulness | 1 | 0.34 | **66%** | 1 / 1 (캐시됨) |
| Context Recall | 1 | 0 | **100%** | 0 / 1 (캐시됨) |
| Answer Relevancy | 1 (+ 임베딩) | 0 | **100%** (임베딩 불필요) | 0 / 1 (캐시됨) |

- **JEV 비용**: 입력 토큰 100만 개당 $0.042다. Phase 1~4 실측 기준으로 **1,000샘플당 $0.04~0.19**다.
- **LLM 비용**: OAuth 프록시를 거쳐 호출해 금액을 재지 못했다. 그래서 위 표에서 호출 수로 비교했다.
- **재판정 범위**: Hybrid가 LLM으로 다시 판정하는 단위는 전체의 5.8%(Context Precision), 8.8%(Faithfulness), 0%(Context Recall)뿐이다.

## 4. 정확도

모든 지표는 사람 라벨 또는 정답이 정해진 합성 변형과 비교해 계산했다.

### 4.1 Faithfulness (응답 단위 hallucination 탐지)

| 데이터 | 지표 | RAGAS | JEV만 | Hybrid | Hybrid − RAGAS |
|---|---|---|---|---|---|
| RAGTruth QA (영어, 전문가 라벨 320응답) | AUROC | 0.790 | 0.809 | **0.830** | **+0.040** |
| | Precision | 0.623 | 0.706 | **0.750** | **+0.127** |
| | Recall | **0.950** | 0.867 | 0.835 | −0.115 |
| | F1 | 0.752 | 0.778 | **0.790** | **+0.038** |
| 한국어 합성 (192응답) | AUROC | 0.944 | 0.962 | **0.970** | **+0.026** |
| | F1 | 0.953 | **0.958** | 0.951 | −0.002 (비슷함) |

- RAGAS가 hallucination이라고 판정한 응답의 37.7%는 실제로 hallucination이 아니었다. RAGAS-JEV는 이 비율이 25.0%다. **오탐이 약 3분의 1 줄었다.**
- 대신 recall은 RAGAS가 더 높다. 판정 임계값(현재 0.5)을 조정하면 precision과 recall 사이의 균형을 바꿀 수 있다. 임계값에 영향을 받지 않는 AUROC는 RAGAS-JEV가 높다.

### 4.2 Answer Relevancy (쌍 정확도, 1.0이 최고, 0.5는 우연 수준)

| 비교 | RAGAS | RAGAS-JEV | 차이 |
|---|---|---|---|
| WikiEval: 좋은 답 > 부족한 답 | 0.720 | **0.920** | **+0.200** |
| 원본 > 무관 문장을 끼워 넣은 답 | 0.605 / 0.490 | **0.980 / 0.950** | **+0.375 / +0.460** |
| 원본 > 답하지 않는 답 | 0.900 / 0.960 | **0.970 / 0.980** | **+0.070 / +0.020** |

관련성 점수는 답의 사실 여부에 영향을 받지 않아야 한다. 그래서 원본과 틀린 답의 평균 점수 차는 0에 가까울수록 좋다.

| 데이터 | RAGAS | RAGAS-JEV |
|---|---|---|
| WikiEval | 0.038 | 0.008 |
| 한국어 | 0.136 | **0.013 (10배 작음)** |
| 영어 | 0.047 | 0.012 |

RAGAS는 무관 문장이 섞인 답변을 **우연 수준으로만 구분한다**. 영어에서는 오히려 우연보다 낮다.

단, RAGAS는 로컬 다국어 임베딩(`paraphrase-multilingual-MiniLM-L12-v2`)으로 실행했다. 프록시에 임베딩 API가 없어서다. 공식 구성인 OpenAI 임베딩보다 불리할 수 있다.

### 4.3 Context Precision

**질문만 보는 판정 (MIRACL, 사람 라벨 526샘플)**

| 지표 | RAGAS (`ContextRelevance`) | JEV만 | Hybrid | Hybrid − RAGAS |
|---|---|---|---|---|
| Spearman (사람 라벨 관련 비율과) | 0.111 / 0.253 | 0.621 / 0.544 | **0.681 / 0.567** | **+0.570 / +0.314** |
| MAE | 0.808 / 0.688 | 0.228 / 0.178 | **0.079 / 0.121** | **오차 90% / 82% 감소** |
| 전부 무관한 세트의 평균 점수 (정답 0) | 0.586 | 0.188 | **0.056** | **오차 10배 작음** |

이 조건에서 RAGAS는 정의가 다른 `ContextRelevance` 외에는 쓸 수 있는 metric이 없다. reference가 없으면 RAGAS `ContextPrecision`은 실행되지 않는다. 그래서 이 차이의 일부는 정의 차이에서 온다. 다만 **reference 없이도 precision을 잴 수 있다는 것 자체**가 RAGAS-JEV의 장점이다.

**reference를 쓰는 판정 (400샘플, 사람 라벨로 계산한 AP 기준)**

| 지표 | RAGAS (`ContextPrecision`) | JEV만 v3 | Hybrid v3 (재보정) | Hybrid − RAGAS |
|---|---|---|---|---|
| AP Kendall | 0.459 / 0.518 | 0.518 / 0.523 | **0.537 / 0.545** | **+0.078 / +0.027** |
| AP Spearman | 0.560 / 0.645 | 0.645 / 0.639 | **0.650 / 0.646** | **+0.090 / +0.001** |
| AP MAE | 0.128 / 0.126 | 0.123 / 0.122 | **0.117 / 0.115** | **−0.011 / −0.011** (오차 9% 감소) |
| AP Pearson | 0.638 / **0.696** | **0.674** / 0.672 | 0.644 / 0.672 | +0.006 / −0.024 |
| 판정용 LLM 호출/샘플 | 5 | **0** | 0.28 / 0.42 | 92~94% 감소 |

JEV만 쓴 v3는 LLM 호출 없이 한국어 AP 지표 4개(Pearson, Spearman, Kendall, MAE)가 모두 RAGAS보다 낫다. 영어에서는 AP Pearson만 RAGAS가 높다 (0.696 vs 0.672).

## 5. 재현성

같은 80개 응답(RAGTruth)을 캐시 없이 두 번 평가했다.

| 지표 | RAGAS | LLM Judge | JEV만 | 개선 (RAGAS 대비) |
|---|---|---|---|---|
| 응답 판정(hallucination 여부)이 뒤집힌 비율 | 6.2% | 1.2% | **0.0%** | **뒤집힘 없음** |
| 샘플 점수 평균 차이 | 0.040 | 0.022 | **0.003** | **13배 작음** |
| 샘플 점수 최대 차이 | 0.333 | 0.201 | **0.017** | **20배 작음** |
| claim 판정이 뒤집힌 비율 | – | 3.1% | **0.4%** | – |

- RAGAS-JEV는 분해 결과와 판정 결과를 모두 캐시한다. 캐시를 쓰면 **점수가 비트 단위로 같게** 나온다.
- 점수 계산도 결정적이다. 합산에 `math.fsum`을 써서 입력 순서에 따라 결과가 달라지지 않는다.
- 판단 유형에 따라 JEV의 안정성은 다르다. Context Precision(Phase 1)에서는 캐시 없이 다시 요청하면 JEV p가 최대 0.83까지 변했다.

## 6. RAGAS에 없는 측정값

아래 값은 RAGAS가 제공하지 않아 수치로 직접 비교할 수 없다. 대신 RAGAS-JEV에서 새로 얻을 수 있는 정보다.

| 항목 | RAGAS-JEV가 내는 값 | 쓰임 |
|---|---|---|
| 판정 신뢰도 | 단위별 confidence와 uncertainty, metric별 평균, 저신뢰 판정 수 | 믿기 어려운 판정을 골라낸다 |
| 재판정 범위 | 전체 단위의 5.8~8.8%만 LLM이 다시 판정 | LLM 비용을 저신뢰 구간에만 쓴다 |
| 사람 검수 대상 | LLM과 JEV가 반대로 판정한 단위만 검수 큐로 보낸다 | 사람이 검수할 양이 준다 |
| 확률 보정 | 질문 × 언어별 보정. 재판정과 함께 쓰면 JEV만 쓴 경우보다 MIRACL Context Precision MAE가 0.228 → 0.079 (한국어)로 줄었다 | 점수를 실제 관련 비율에 맞춘다 |
| 판정 근거 추적 | 단위마다 원래 JEV 확률, 보정된 확률, 판정 출처(`jev`, `llm_auditor`, `strong_judge`, `human`)를 기록한다 | 점수 하나를 claim이나 chunk까지 거슬러 확인할 수 있다 |

## 7. 우위가 아닌 항목 (해석 시 주의)

| 항목 | 결과 | 이유 |
|---|---|---|
| Context Recall | RAGAS가 근소하게 앞선다. Pearson 0.909 / 0.944 vs Hybrid 0.903 / 0.938 (차이 0.006 이하) | 정답을 reference **문장** 단위로 만들어, 같은 단위로 판정하는 RAGAS에 유리했다 |
| Faithfulness recall | RAGAS 0.950 vs Hybrid 0.835 | RAGAS는 많이 잡는 대신 오탐이 많다. AUROC와 F1은 RAGAS-JEV가 높다 |
| 영어 Context Precision AP Pearson | RAGAS 0.696 vs 0.672 | 다른 AP 지표(Kendall, Spearman, MAE)는 RAGAS-JEV가 같거나 낫다 |
| 처음 평가할 때 속도 (Recall, Answer Relevancy) | 거의 같다 (1.0~1.3배) | LLM 분해가 시간 대부분을 차지한다. 차이는 다시 평가할 때 커진다 |
| 보정 의존성 | 분포가 다른 데이터에 기본 보정을 쓰면 가장 나빴다 (AP Pearson 0.390 / 0.516) | 서비스 도메인에서는 [도메인 재보정](도메인_재보정_가이드.md)이 필수다 |

그 밖의 한계:

- **합성 데이터**: 일부 데이터(한국어 Faithfulness, Context Recall, Answer Relevancy의 MIRACL 세트)는 `gpt-6-astra`로 만든 합성 데이터다.
- **도메인**: 모든 데이터가 Wikipedia·웹 기반의 일반 도메인이다.
- **LLM 판정의 변동**: LLM 판정은 결정적이지 않다. 1~2%p 차이는 다시 돌리면 바뀔 수 있다.
- **속도 수치**: RAGAS-JEV의 속도는 요청 단위 지연을 더한 추정치다 (2.1절).
