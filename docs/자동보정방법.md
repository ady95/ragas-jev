# 자동 보정 사용 방법 (0.3.0)

- 대상 버전: `ragas-jev` 0.3.0 이상 (`pip install -U ragas-jev`)
- 관련 문서: [자동 보정 검증 리포트](reports/auto_calibration.md), [도메인 재보정 가이드](도메인_재보정_가이드.md), [보정 방법 상세 설명](보정방법_살세설명.md), [사용 방법](ragas-jev_사용방법.md)

0.3.0에서 쓸 수 있는 기능은 네 가지입니다.

| 기능 | 명령 | 라벨 | 추가 API 호출 |
|---|---|---|---|
| 라벨 없는 비율 조정 | `calibration adapt` | 불필요 | 없음 |
| 비율 차이 경고 | `evaluate --calibrate`를 쓰면 자동으로 표시 | 불필요 | 없음 |
| LLM 사전 라벨 | `calibration sample --prelabel` | 사람이 확인 | LLM 호출 |
| 라벨 비율 저장 | `calibration fit`이 자동으로 기록 | – | – |

## 1. 라벨 없이 보정하기: `calibration adapt`

```bash
# ① 보정 없이 평가 (JEV 원래 확률 얻기). 비용을 줄이려면 LLM 재판정은 끔
ragas-jev evaluate -i data.jsonl -o results/raw.jsonl --no-audit

# ② 이 데이터의 라벨 비율에 맞춰 기본 곡선을 조정
ragas-jev calibration adapt -r results/raw.jsonl -o adapted.json

# ③ 조정된 곡선으로 다시 평가 (출력 파일은 새 이름으로)
ragas-jev evaluate -i data.jsonl -o results/adapted.jsonl --calibration adapted.json
```

②의 출력은 이렇게 읽습니다.

```
  key | units | base map | yes rate: calibration data | estimated here | result
  chunk_relevance.v2:ko | 1000 | chunk_relevance.v2:ko | 0.135 | 0.490 | adapted
  chunk_relevance.v3:ko | 1000 | - | - | - | no base map: fit one from labels (calibration sample / fit)
```

| 열 | 뜻 |
|---|---|
| `yes rate: calibration data` | 기본 곡선을 학습한 데이터의 "예" 비율입니다. 예를 들어 0.135는 관련 문서가 13.5%라는 뜻입니다 |
| `estimated here` | 라벨 없이 추정한 이 데이터의 "예" 비율입니다. 앞 열과의 차이가 클수록 기본 곡선이 이 데이터에 맞지 않고, 그만큼 조정 효과도 큽니다 |
| `adapted` | 곡선을 조정해 파일에 넣었습니다 |
| `no base map` | 조정할 기본 곡선이 없는 문항입니다. `chunk_relevance.v3`(reference가 있는 Context Precision)와 `statement_relevance.v2`(Answer Relevancy)가 해당하며, 원래 확률을 그대로 씁니다 |

옵션:

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `--base 파일` | `RAGAS_JEV_CALIBRATION_FILE`이 있으면 그 파일, 없으면 패키지 기본 보정 | 조정할 원래 보정 파일입니다. 도메인 재보정 파일을 새 데이터에 맞출 때도 씁니다 |
| `--min-units N` | 50 | unit이 이보다 적은 문항은 조정하지 않습니다. 적으면 비율 추정이 불안정합니다 |

③을 실행할 때 알아 둘 점:
- **비용**: JEV 판정과 claim 추출은 캐시를 재사용하므로 JEV를 다시 호출하지 않습니다. 다만 `--no-audit`를 빼면 보정된 신뢰도로 재판정 대상을 새로 고르므로 LLM 호출이 생깁니다.
- **같은 데이터를 계속 평가할 때**: `.env`에 `RAGAS_JEV_CALIBRATION_FILE=adapted.json`을 넣으면 매번 옵션을 줄 필요가 없습니다.

## 2. 보정을 켰을 때 뜨는 경고

`--calibrate`나 `--calibration`으로 평가하면, 추정 비율이 보정 데이터의 비율과 **0.15 이상** 다른 문항을 알려 줍니다.

```
note: ref_claim_coverage.v1:ko: estimated yes rate 0.80 vs 0.53 in the calibration data.
The map may not fit this data; try `ragas-jev calibration adapt -r results/out.jsonl -o adapted.json` or domain re-calibration
```

이 경고가 뜨면, 방금 나온 결과 파일로 1절의 ②와 ③을 실행하면 됩니다.

## 3. 사람 라벨 작업을 빠르게: `--prelabel`

절대 점수가 중요하거나 경고가 계속 뜨면, 사람 라벨로 곡선을 다시 학습하는 게 가장 정확합니다. 이때 LLM 판정을 먼저 채워 두면 작업이 빨라집니다.

```bash
ragas-jev calibration sample -r results/raw.jsonl -s data.jsonl -o sheet.csv --prelabel
#   --prelabel-model gpt-6-luna   # 모델 변경 (기본: RAGAS_JEV_STRONG_JUDGE_MODEL)
#   --pii-masking                 # 시트 텍스트를 마스킹한 뒤 LLM에 전송
```

시트에는 두 열이 추가됩니다.

| 열 | 내용 |
|---|---|
| `llm_p` | LLM이 준 확률 |
| `llm_label` | LLM 판정 (0/1). **참고용입니다** |
| `label` | **비어 있습니다.** 사람이 `llm_label`을 보고 확인하거나 고쳐서 적습니다 |

```bash
ragas-jev calibration fit -l sheet.csv -o domain_calibration.json   # label 열만 읽음
ragas-jev evaluate -i data.jsonl -o results/domain.jsonl --calibration domain_calibration.json
```

- **왜 `label`을 비워 두나**: LLM 판정을 그대로 라벨로 쓰면 LLM의 성향이 곡선에 들어갑니다. 검증에서 LLM이 사람보다 엄격했던 영어 Faithfulness는 모든 방법 중 가장 나빴습니다([검증 리포트](reports/auto_calibration.md) 4.2절). 그래서 `llm_label`을 `label`에 그대로 복사하지 말고 확인한 뒤 적으세요.
- **데이터 전송**: `--prelabel`은 시트의 질문·claim·context를 LLM 엔드포인트로 보냅니다.

## 4. 어떤 순서로 쓰면 되나

```
평가 (보정 없이)
  → calibration adapt           ← 라벨 없이 바로 가능. 먼저 해 볼 것
  → 경고가 크거나 절대 점수가 중요하면:
       calibration sample --prelabel → 사람이 label 작성 → calibration fit
  → 새 데이터가 들어오면:
       calibration adapt --base domain_calibration.json   ← 도메인 곡선을 새 데이터 비율에 맞춤
```

| 상황 | 권장 |
|---|---|
| 데이터가 벤치마크(공개 Wikipedia·웹 QA)와 비슷함 | `--calibrate` 또는 `adapt`. 둘 다 결과가 비슷합니다 |
| 새 도메인, 라벨 없음 | **`adapt`**. 기본 곡선의 손해를 피합니다 |
| 새 도메인, 절대 점수가 중요함 | `--prelabel` + 사람 라벨 → `fit` |
| reference가 있는 Context Precision도 보정하고 싶음 | v3에는 기본 곡선이 없어 `adapt`가 동작하지 않습니다. 사람 라벨로 `fit`을 한 번 해 두면, 이후에는 `adapt --base`로 새 데이터에 맞출 수 있습니다 |

## 5. 알아 둘 점

- **0.2 이전 보정 파일**: 라벨 비율(`priors`)이 없어서 `adapt`가 "no stored prior"로 건너뜁니다. 라벨 시트로 `calibration fit`을 다시 실행하면 비율이 함께 저장됩니다.
- **표본이 너무 작을 때**: 문항별 unit이 수십 개 수준이면 비율 추정이 흔들립니다(`--min-units` 기본 50).
- **`adapt`로 고칠 수 없는 것**: 비율만 맞추고 곡선 모양은 고치지 못합니다. 절대값 정확도는 사람 라벨 재보정이 더 좋습니다.

## 6. Python에서 쓰기

```python
from pathlib import Path
from ragas_jev.config import get_settings
from ragas_jev.schemas import SampleResult
from ragas_jev.scoring.adaptation import adapt_calibration
from ragas_jev.scoring.calibration import Calibrator

results = [SampleResult.model_validate_json(l) for l in Path("results/raw.jsonl").read_text(encoding="utf-8").splitlines() if l.strip()]
adapted, report = adapt_calibration(results, Calibrator.load(get_settings().calibration_path))
for k in report.keys:
    print(k.key, k.source_prior, k.estimated_prior, k.adapted, k.note)
adapted.save(Path("adapted.json"))
```
