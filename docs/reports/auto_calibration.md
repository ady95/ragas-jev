# 자동 보정 검증 리포트: 평가 데이터만으로 보정할 수 있는가

- 실행일: 2026-09-27
- 스크립트: [run_auto_calibration.py](../../benchmark/run_auto_calibration.py) (API 호출 없음)
- 관련 문서: [Phase 5 리포트](phase5_routing_calibration.md), [Phase 6 리포트 9절](phase6_benchmark.md), [보정 방법 상세 설명](../보정방법_살세설명.md)

## 1. 요약

평가 데이터에서 보정 데이터를 자동으로 만드는 두 방법을, 기존 벤치마크에 저장된 판정으로 검증했습니다. 사람 라벨은 **채점에만** 썼습니다.

| 방법 | 방식 | 결과 |
|---|---|---|
| **C. 라벨 없는 비율 조정** | 평가 데이터의 JEV 확률 분포만 보고 실제 "예" 비율을 추정(EM)해, 기본 곡선을 그 비율에 맞게 옮김 | **10개 시나리오 중 9개에서, "보정 없음"과 "기본 곡선" 중 나은 쪽과 같거나 더 좋았습니다** (샘플 MAE 차이 −0.008 ~ +0.001). 기본 곡선이 크게 손해 보던 분포 차이 사례를 자동으로 피합니다. 나머지 1개도 +0.010 차이에 그쳤습니다 |
| **B. LLM 라벨** | `gpt-6-sol` 판정(p ≥ 0.5)을 라벨로 삼아 곡선을 학습 | 샘플 MAE는 12개 중 8개에서 가장 좋았습니다. 하지만 unit 보정 오차(ECE)는 대부분 나빠졌고, **LLM이 사람보다 엄격한 영어 Faithfulness에서는 가장 나빴습니다.** LLM의 성향이 곡선에 들어갑니다 |
| 사람 라벨 (비교 기준) | 평가 데이터의 사람 라벨로 2-fold 재보정 | unit ECE는 거의 항상 가장 좋았습니다. 샘플 MAE는 표본이 작으면 오히려 흔들렸습니다 |

**결론**
- **C는 `--calibrate`의 안전장치로 쓸 만합니다.** 분포가 같으면 기본 곡선의 이득을 그대로 유지하고, 분포가 다르면 기본 곡선의 손해를 피합니다. 라벨과 비용이 전혀 들지 않습니다.
- **B는 단독으로 쓰기엔 위험합니다.** 사람 라벨 작업의 **사전 라벨**(사람이 확인·수정)로 쓰는 편이 맞습니다.
- **절대값 보정의 정확도(ECE)는 여전히 사람 라벨이 가장 좋습니다.** 두 자동 방법 모두 도메인 재보정을 대신하지는 못합니다.

## 2. 방법

### 2.1 비교한 보정

| 이름 | 곡선 | 쓰는 정보 |
|---|---|---|
| 보정 없음 | 없음 (0.2.0 기본값) | – |
| 기본 곡선 | **다른 데이터(source)** 의 사람 라벨로 학습한 isotonic 곡선. 패키지 기본 보정과 같은 상황 | source 라벨 |
| C: 비율 조정 | 기본 곡선의 출력 q를 목표 데이터의 추정 비율 π_t에 맞게 조정: `q' = w1·q / (w1·q + w0·(1−q))`, `w1 = π_t/π_s`, `w0 = (1−π_t)/(1−π_s)`. π_t는 목표 데이터의 q로 EM 반복 추정 (Saerens et al., 2002) | source 라벨 비율 π_s + 목표 데이터의 **라벨 없는** JEV 확률 |
| B: LLM 라벨 | 목표 데이터의 JEV 확률과 `gpt-6-sol` 판정(p ≥ 0.5)으로 isotonic 학습 | 목표 데이터의 LLM 판정 |
| 사람 라벨 | 목표 데이터의 사람 라벨로 질문 단위 2-fold 교차 학습 | 목표 데이터의 사람 라벨 (비교 기준) |

C의 가정은 "라벨 비율만 바뀌고, 같은 라벨 안에서 JEV 확률이 나오는 방식은 그대로"라는 것입니다(label shift). 곡선 모양 자체가 다른 경우는 고치지 못합니다.

### 2.2 시나리오

| 시나리오 | source (기본 곡선 학습) | target (평가) | 라벨 비율 변화 |
|---|---|---|---|
| `cp_shift` | MIRACL Phase 1 (이 세트의 질문 제외) | reference 기반 Context Precision 세트, `chunk_relevance.v2` | 관련 비율 0.06 / 0.25 → 0.44 / 0.42. **Phase 6에서 기본 보정이 실패한 사례** |
| `cp_v3` | 없음 | 같은 세트, `chunk_relevance.v3` | 기본 곡선이 없어 B와 사람 라벨만 해당 |
| `recall_kept` | Recall 질문 절반, 모든 조건 | 나머지 절반, `none` 조건 제외 | 지지 비율 0.53 → 0.80. bench40처럼 검색이 대부분 성공한 경우 |
| `recall_same` | 같은 절반 | 나머지 절반, 모든 조건 | 변화 없음 (점검용) |
| `faith_halluc` | 응답 절반 | 나머지 절반 중 hallucination 있는 응답만 | 지지 비율 0.84 / 0.82 → 0.73 / 0.75 |
| `faith_same` | 같은 절반 | 나머지 절반 전체 | 변화 없음 (점검용) |

한국어와 영어를 따로 계산했습니다(시나리오 이름 뒤 `/ko`, `/en`).

- **Context Precision**: 샘플 점수는 AP입니다. 예/아니오 판정은 보정된 p ≥ 0.5입니다.
- **Recall, Faithfulness**: 샘플 점수는 unit p의 평균이고, 정답은 샘플 안에서 지지된 unit의 비율입니다.
- **LLM 재판정**: 적용하지 않았습니다. 보정 자체의 효과만 봤습니다.

## 4. 해석

### 4.1 C: 라벨 없는 비율 조정

- **기본 곡선의 실패를 자동으로 피합니다.**
  - `cp_shift/ko`: 기본 곡선이 MAE를 0.141에서 0.334로 망쳤는데, C는 0.140으로 되돌렸습니다.
  - `recall_kept`: bench40과 같은 현상(검색이 대부분 성공한 데이터에서 기본 Recall 곡선이 과소평가)이 재현됐고, C가 이를 없앴습니다.
- **분포가 같으면 기본 곡선의 이득을 유지합니다.** `recall_same`과 `faith_same`에서 C는 기본 곡선과 거의 같았습니다. 조정이 필요 없을 때 추정 비율도 실제 비율과 가까웠습니다(0.52~0.58 대 0.53, 0.84~0.90 대 0.86~0.88).
- **비율 추정이 빗나가도 결과는 안전했습니다.** `cp_shift/ko`는 실제 0.44를 0.55로 추정했지만, 결과는 "보정 없음"과 같았습니다. 영어는 0.42를 0.42로 정확히 추정해 ECE가 0.121(보정 없음)에서 0.066으로 줄었습니다.
- **유일하게 나빴던 사례**: `faith_halluc/ko`에서 +0.010이었습니다. 비율 변화가 작고(0.84 → 0.73) unit이 209개뿐인 경우입니다.
- **사람 라벨만큼 정확하지는 않습니다.** unit ECE는 대부분 사람 라벨 재보정이 더 좋았습니다(예: `cp_shift/en` 0.066 대 0.036). C는 라벨 비율만 맞출 뿐, 곡선 모양은 고치지 못합니다.
- **v3에는 쓸 수 없습니다.** 기본 곡선이 없는 문항(`chunk_relevance.v3`)은 조정할 대상이 없습니다.

### 4.2 B: LLM 라벨

- **샘플 MAE는 자주 가장 좋았습니다.** 특히 Recall에서 LLM 라벨이 사람 라벨과 95~96% 일치해 효과가 컸습니다(0.069 / 0.066).
- **unit ECE는 대부분 나빠졌습니다.** LLM 라벨의 "예" 비율이 실제와 달라, 곡선이 LLM 쪽 비율로 끌려갑니다. 예를 들어 v3 Context Precision은 LLM 0.59, 실제 0.44였습니다.
- **LLM이 더 엄격하면 곡선도 엄격해집니다.** 영어 Faithfulness에서 LLM 라벨 비율은 0.68 / 0.78로, 실제 0.75 / 0.88보다 낮았습니다. 그 결과 B가 모든 방법 중 가장 나빴습니다(MAE 0.133 / 0.134). bench40에서 본 "sol은 계산 결과 claim을 거부한다"는 성향과 같은 방향입니다.
- **데이터가 외부 LLM으로 나갑니다.** 이 실험은 저장된 판정을 썼지만, 실제로는 목표 데이터를 LLM으로 판정해야 합니다.

### 4.3 사람 라벨 재보정

- unit ECE는 거의 항상 가장 좋았습니다. 절대값 보정에는 여전히 사람 라벨이 기준입니다.
- 목표 데이터가 작으면(209~393 unit) 2-fold로 학습한 곡선이 흔들려, 샘플 MAE가 오히려 나빠지기도 했습니다(`faith_halluc/ko` 0.108). 도메인 재보정 가이드의 "문항 × 언어별 최소 100개 이상" 기준이 하한이라는 점을 보여 줍니다.

## 5. 한계

1. **분포 차이를 일부러 만든 시나리오가 있습니다.** `recall_kept`와 `faith_*`는 같은 데이터셋을 나누고 라벨 비율을 바꾼 것입니다. 실제 도메인 차이(용어, 문서 형식)는 비율 차이 외의 변화도 포함합니다. 실제 분포 차이 사례는 `cp_shift`(MIRACL 일반 질문 → reference 기반 세트) 하나입니다.
2. **LLM 재판정을 빼고 계산했습니다.** 실제 Hybrid에서는 보정된 신뢰도에 따라 재판정 대상이 바뀝니다.
3. **B는 `gpt-6-sol` 하나로만 시험했습니다.** 여러 LLM이 일치한 것만 쓰는 방식은 시험하지 않았습니다.
4. **데이터 크기**: 목표 데이터는 209~1,806 unit입니다. 더 작은 평가 세트에서는 C의 비율 추정이 불안정해질 수 있습니다.

## 6. 제안

| 우선 | 제안 | 구현 방식 |
|---|---|---|
| 1 | **C를 `calibration adapt` 명령으로 제공** | 보정 없이 평가한 결과를 받아, 문항 × 언어별로 비율을 추정하고 조정된 곡선을 새 보정 파일로 씁니다. 조정된 곡선도 단조 증가라 지금 보정 파일 형식을 그대로 쓸 수 있습니다. 그 파일로 `evaluate --calibration`을 다시 돌리면 JEV 판정은 캐시를 재사용합니다. 파이프라인은 바꿀 필요가 없습니다 |
| 1-1 | 보정 파일에 **학습 데이터의 라벨 비율(π_s)** 저장 | C에 필요합니다. `calibration fit`은 이미 계산하고 있어 저장만 하면 됩니다(`yes rate`). 패키지 기본 보정 파일에도 Phase 5 데이터로 추가합니다 |
| 1-2 | 비율 차이가 크면 경고 | 예: "이 데이터의 추정 비율 0.80이 기본 곡선의 학습 비율 0.53과 크게 다릅니다. `calibration adapt`나 도메인 재보정을 권합니다" |
| 2 | **B는 라벨 시트의 사전 라벨로 제공** | `calibration sample --prelabel`로 LLM 판정을 `llm_label` 열에 채워, 사람이 확인·수정하게 합니다. 사람 작업 시간을 줄이는 용도입니다 |
| 3 | v3 문항의 기본 곡선 | C를 쓰려면 source 곡선이 필요합니다. 사람 라벨이 있는 도메인 데이터로 v3 곡선을 먼저 만들어야 합니다 |

## 7. 구현 (0.3.0)

6절의 제안 1~2를 구현했습니다.

| 기능 | 명령·위치 |
|---|---|
| C: 라벨 없는 비율 조정 | `ragas-jev calibration adapt -r results.jsonl -o adapted.json` (`ragas_jev.scoring.adaptation`) |
| 학습 데이터 라벨 비율 저장 | 보정 파일의 `priors`. `calibration fit`이 기록하고, 패키지 기본 보정 파일에도 추가 (곡선은 그대로) |
| 비율 차이 경고 | `evaluate --calibrate` / `--calibration` 후 차이가 0.15 이상인 문항을 안내 |
| B: LLM 사전 라벨 | `calibration sample --prelabel` → `llm_p`, `llm_label` 열 (`label`은 비움) |

구현한 명령을 Phase 6의 reference 기반 Context Precision 결과(v2)에 그대로 실행했습니다. 기본 곡선은 **패키지 파일**로, 2절 실험처럼 이 세트의 질문을 뺀 곡선이 아닙니다.

| | 보정 없음 | 기본 보정 (패키지) | `calibration adapt` |
|---|---|---|---|
| 한국어 unit ECE / AP MAE | 0.113 / 0.141 | 0.143 / 0.221 | **0.069 / 0.137** |
| 영어 unit ECE / AP MAE | 0.121 / **0.183** | 0.100 / 0.235 | **0.057** / 0.193 |
| 추정 비율 (실제) | – | 학습 비율 0.135 / 0.271 | 0.490 / 0.408 (실제 0.44 / 0.42) |
